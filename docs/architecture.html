Dental Triage Blueprint

Architecture and user flows for an AI triage platform that connects patients with subscribed dental clinics. It has four roles: patient, dentist, clinic admin and super admin. Each case gets one of three outcomes:

RED · ER / ambulance now ORANGE · Same-day dentist GREEN · Home care + routine booking
1

System architecture

All four roles reach the backend through one login and permission layer. The triage service always runs the red-flag rules before asking the AI model. Red cases go straight to emergency services. Orange and green cases go to the matching engine, which only considers subscribed clinics. Every AI call goes through one AI gateway, which handles retries, caching and switching between providers.

AI provider fallback

How the AI gateway handles Groq's free-tier rate limit. Every request first tries Groq, then the local Ollama model, then a rules-only mode with fixed questions and answer buttons. The red-flag rules never depend on the AI, so triage keeps working even if every AI service is unavailable.

  W -->|retries used up| O["Call Ollama

  O -->|fails| RO["Rules-only mode
fixed questions + buttons"]
  VAL -->|yes| OUT["Send to triage rules
+ save in cache"]
  VAL -->|no, retry once| G
  RO --> OUT2["Triage continues
without AI"]

Orange case dispatch

This is how an urgent case reaches a dentist in the network. If a clinic doesn't respond within 10 minutes, the case moves to the next clinic, so no patient is left waiting on one clinic.

  autonumber

  participant B as Clinic B dentist
  P->>T: Symptoms + photo
  T->>T: Red-flag check, then AI score
  T-->>P: ORANGE · same-day dentist
  T->>M: Case + location + urgency
  M->>M: Filter subscribed clinics
open now · free slot · specialty
  M->>A: Alert with AI summary
  Note over M,A: 10-minute timeout
  A--xM: No response
  M->>B: Alert with AI summary
  B->>M: Accept
  M-->>P: Confirmed · Clinic B · directions
  B-->>P: Pre-visit instructions

Case lifecycle

These are the states a TriageCase moves through. The dentist dashboard and the admin statistics both read these states.

stateDiagram-v2
  [*] --> Triage
  Triage --> Emergency: red flag
  Triage --> Pending: orange
  Triage --> SelfCare: green
  Pending --> Offered: clinic alerted
  Offered --> Pending: timeout or declined
  Offered --> Accepted: dentist accepts
  Accepted --> Treated: visit done
  Treated --> FollowUp
  SelfCare --> FollowUp: check-in due
  FollowUp --> Triage: getting worse
  FollowUp --> Closed: resolved
  Emergency --> Closed: handed to ER
  Closed --> [*]
Safety rule: red cases always leave the network and go to the ER or 112, whether or not a subscribed clinic is nearby. Paying clinics never get priority over patient safety.
